Делегаты в C# нужны для хранения ссылок на методы. Это позволяет:
Определять вызываемый метод не при компиляции, а во время выполнения программы.
Обеспечивать связь между объектами по типу «источник — наблюдатель». Например, делегат может указывать на метод, который должен быть вызван при изменении состояния одного объекта, а в вызываемом методе можно получать информацию о состоянии вызывающего объекта и посылать ему сообщения.
Создавать универсальные методы, в которые можно передавать другие методы.
Поддерживать механизм обратных вызовов. Например, делегат может указывать на метод, который должен быть вызван при нажатии кнопки.
Передавать делегатов в методы в качестве параметра. Это обеспечивает функциональную параметризацию: в метод можно передавать не только различные данные, но и различные функции их обработки.
Принцип работы
Делегат хранит адрес метода, позволяя вызвать его без необходимости вызывать его напрямую. Методы соответствуют делегату, если они имеют один и тот же возвращаемый тип и один и тот же набор параметров. Но во внимание также принимаются модификаторы ref, in и out.
Чтобы воспользоваться делегатом, необходимо создать его экземпляр и задать имена методов, на которые он будет ссылаться. При вызове экземпляра делегата вызываются все заданные в нём методы.
Некоторые особенности работы делегатов:
Делегат может хранить ссылки на несколько методов и вызывать их поочерёдно.
Можно добавлять в список вызова делегата несколько методов (для этого используется операция +=).
Делегат — неизменяемый тип данных, поэтому при любом изменении создаётся новый экземпляр, а старый впоследствии удаляется сборщиком мусора.

Групповые делегаты (Multicast delegates) — позволяют собрать цепочку вызовов из нескольких методов. Эта цепочка всегда запускает все добавленные в неё методы в том порядке, в котором они были добавлены.
Универсальные делегаты (например, Func, Action, Predicate) — в сигнатуре задаётся тип входных параметров и тип выходного параметра, который всегда идёт последним в списке.
Примеры использования
Реализация обратных вызовов в программировании на основе событий. Например, делегат может указывать на метод, который должен быть вызван при нажатии кнопки.
Передача пользовательских действий методу, изменяя его поведение без изменения его структуры.
Гибкое управление алгоритмами — например, в игре можно передавать пользовательские действия методу, изменяя его поведение.
Ошибки
Делегаты конкретны в том, на что они могут ссылаться. При попытке использовать делегат, предназначенный для ссылки на метод, принимающий целое число и возвращающий строку, с методом, который принимает строку и возвращает целое число, программа не скомпилируется.
