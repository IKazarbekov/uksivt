Вопрос 4
Что выведет на консоль следующая программа и почему?
class Person
{
    public string Name { get; set; }
    public virtual void Display() => Console.WriteLine($"Person {Name}");
}
class Client : Person
{
    public override void Display() => Console.WriteLine($"Client {Name}");
}
     
class Program
{
    delegate void DisplayHandler<T>(T item);
    static void Main(string[] args)
    {
        DisplayHandler<Person> personHandler = PersonInfo;
        DisplayHandler<Client> clientHandler = personHandler;
 
        clientHandler(new Client { Name = "Bob" });
        Console.Read();
    }
    private static void PersonInfo(Person p) => p.Display();
    private static void ClientInfo(Client p) => p.Display();
}

Ответы

Делегат 3- справо синтаксический сахар. Компилятор переобразует из него в левое. В левом более явно а также можно использовать делегат?.Invoke() если нет указателей
Анонимные функции 4- В классе сама инициализует null а в коде нет. Это правило знаем, но
	уточняем. null для делегата это нормально и при += используют комбинирование.
Лямбда 4-  Action  и Func являются делегатами. Func принимает первой класс
	как возвращаемый тип данных, остальные параметры. А в Action только
	параметры
Ковариантность и контрвариантность
	1 - Ковариантность - это возможность передать делегату метод,
		 который возвращает объект типа, производного от возвращаемого типа делегата.
	2 - Контрвариантность - это возможность передать делегату метод, 
		параметр которого является более универсальным по отношению к типу параметра делегата.
	3 - Данный делегат является ковариантным.
		out - можно поставить более общий тип, а in более производный
	4 - Программа не скомпилируется, потому что мы не можем присвоить переменной делегата DisplayHandler<Client> ссылку на объект 
	DisplayHandler<Person>, так как делегат DisplayHandler не контрвариантный. Чтобы программа работала, нам надо изменить делегат следующим образом:
	delegate void DisplayHandler<in T>(T item);
